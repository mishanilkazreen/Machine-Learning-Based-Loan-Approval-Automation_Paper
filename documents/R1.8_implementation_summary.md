## SHAP vs LIME Methodological Comparison

| Dimension | SHAP (TreeExplainer) | LIME (LimeTabularExplainer) |
|---|---|---|
| Scope | Global + local | Local only |
| Theoretical basis | Shapley values (game theory) | Local linear surrogate |
| Consistency | Globally consistent feature attribution | Can vary across runs (random perturbations) |
| Model dependency | Tree-specific (exact for RF) | Model-agnostic |
| Computational cost | Higher (full training set) | Lower (per-instance perturbations) |
| Output | Continuous SHAP values | Weighted feature coefficients |

## Property-Based Test

**File:** `code/test_shap_guard.py`

Tests the `base_val` guard expression across all three input types the SHAP library may produce:

```python
@given(
    st.one_of(
        st.floats(allow_nan=False, allow_infinity=False),
        st.lists(st.floats(...), min_size=2, max_size=2),
        arrays(dtype=np.float64, shape=2, elements=st.floats(...))
    )
)
@settings(max_examples=100)
def test_base_val_guard(expected_value):
    base_val = base_val_guard(expected_value)
    if isinstance(expected_value, (list, np.ndarray)):
        assert base_val == expected_value[1]
    else:
        assert base_val == expected_value
```

**Result:** 1 passed (100 examples generated). Validates Requirements 3.2 and 3.6.

## Known Limitations

### SMOTE Synthetic Instances
Instances 4 and 6 are drawn from `X_train_sm`, which contains SMOTE-generated synthetic samples. The feature values shown in both SHAP and LIME outputs may not correspond to real loan applicants. This is acknowledged in the comparison markdown cells and should be noted in the paper.

### Hardcoded Feature Rankings
Per the design spec, top-3 feature rankings in the comparison markdown cells are manually read from the rendered plot outputs and hardcoded as text. They are not extracted programmatically from plot objects. If the notebook is re-run with a different random seed or model, these rankings may no longer match the rendered outputs.

### SHAP Version Compatibility
The `isinstance(shap_values, list)` branch handles both older SHAP versions (which return a list of arrays) and newer versions (which may return a 3-D array). The guard is in place throughout all indexing expressions.
